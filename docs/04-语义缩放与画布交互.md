# 语义缩放与画布交互

> 2026-11-13：基础空间画布与模块语义导航已实现，先看[四级用户注册](./poc/canvas-engine/registration.html)及[演示与验证](./poc/README.md)。当前每次渲染一层；下文的全层同时 LOD、关系聚合、媒体和变更阅读仍是后续设计建议，当前边界以[起步范围](./00-起步范围.md)为准。

## 当前第一版

以用户指定的 `E:/BenchGo/docs/总架构.html` 为样式与交互参考：大画布、分区、节点卡片、连线，目录和详情按需出现。生成器接受通用 JSON，打包同一份运行时为离线 HTML；支持层级导航、平移缩放、节点详情、当前视图搜索、关系高亮、主题切换、拖动、浏览器保存及布局导出/导入。

AI 负责读取、分析与编排内容，引擎负责校验、呈现和交互，不自动扫描仓库。初始位置来自输入，连线由几何算法避障；不宣称复杂图自动排版。拖动只改布局，不能改业务文本或关系。格式和生成方式见[画布指引](../skills/arkigo/references/canvas.md)。

56px 页头仅显示层级面包屑、搜索图标和浅深切换图标；不再提供独立返回箭头、走读、Tabs 或视图选择框。选中带 `targetViewId` 的模块后，可点击按钮、双击或放大进入；缩小到阈值、祖先面包屑或 `Alt+Left` 返回，并恢复父级相机与选中模块。滚轮/双指每次手势最多跨一级；搜索与适应不会因程序定位自动深入。

进入判断取决于选中模块相对可用画布的投影大小、可见性与主动放大方向；返回使用独立阈值和手势锁，避免同一次手势反复跨层。230ms 空间展开/收回保持父子模块的视觉关联；键盘或减少动态效果偏好下立即完成。`rootViewId` 可选，默认第一个视图；`targetViewId` 必须组成无自指、无环、无多父、全部可达的单根树。

当前模块钻取每次只渲染活动层，过渡时短暂保留旧场景。它尚未实现所有层级同时存在的 LOD、跨层关系聚合或大图裁剪，也没有无限图性能承诺。以下章节保留完整体验设计，未在本节列出的能力仍待实现或验证。

## 核心体验

同一个用户模块，缩远时是一块标题清楚的区域；放大后区域内部出现登录、注册、权限；继续深入登录流程，显现步骤、规则、异常和验收。对象身份始终不变，用户能知道自己处在系统的哪个位置。

缩放控制展示密度，进入模块控制阅读范围。这两个操作可以联动，但不能把一个固定的缩放百分比等同于业务层级；屏幕大小、模块尺寸与层级深度都不相同。

## 展示密度

| 密度 | 在画布中显示 | 详情面板补充 |
| --- | --- | --- |
| 概览 | 模块名称、一句职责、问题/变更计数、聚合连接 | 模块目的和范围 |
| 结构 | 子模块、主流程、重要依赖、输入输出摘要 | 关联规则和未决问题列表 |
| 行为 | 流程步骤、分支条件、规则及验收摘要 | 完整规则、异常、附件、版本差异和代码证据 |

“代码与证据”主要在行为层的详情面板按需读取，避免把所有源码铺到无限画布上。以后可以增加专门证据视图，但不能要求不断滚轮放大才能访问代码。

## 缩放和导航规则

- 使用节点的屏幕投影尺寸判断是否适合显示更多内容，具体阈值由原型实测，不在数据模型中写死。
- 展开与收起使用不同阈值，避免临界点来回闪烁；优先展开用户聚焦的模块，限制一次同时展开的对象数量。
- 显示内容增加时保持父模块的空间锚点稳定；必要时进入模块内部视图，不让所有邻居在每次缩放时重新排列。
- 双击或“进入模块”可进入上下文，面包屑返回；键盘提供相同入口。
- 手动锁定展开或收起的意图优先于自动缩放，提供“恢复自动”操作。
- 搜索结果可以展开祖先并定位对象；深链接使用 `projectId + nodeId`，不依赖坐标或标题。
- 无更多内容时明确显示“尚未设计”，不生成虚构的子模块来填充画布。

## 两种关系同时存在

模块区域表达归属，连接线表达具体关系。跨模块的规则和依赖允许穿过容器边界。

当细节被隐藏时，将已记录关系投影到当前可见的最近祖先。例如两条步骤依赖可以在全景显示为“用户模块 → 通知模块，2 条依赖”。聚合关系保存原始关系 ID，点击可展开来源；同一父模块内部的隐藏连接不变成伪造的自环。

不同 `kind` 和方向分别聚合，不能把“验收覆盖”和“运行依赖”混为一条线。根据关系图得到的影响范围标注为“设计关联范围”；真实运行影响需要额外依据。

## 内容与媒体

文本摘要随密度变化，完整规则可在面板阅读。图片在可见时加载缩略图，原型链接显示标题和来源。音视频首版以附件链接呈现，不自动播放；后续再增加预览。

外部原型或第三方 HTML 不直接作为不受约束的脚本嵌入画布。首版使用链接或受限制的预览，避免一份附件修改整个工作区。附件不能遮挡对象身份、状态和关系。

## 变更阅读

用户选择基线和候选设计后，画布保持稳定布局，以徽标、文字和描边区分：

- 新增：新增对象或关系。
- 修改：展开可看字段前后值。
- 删除：从基线提供可点开的旧对象表示。
- 关联影响：本身未改，但由明确关系与修改项相关；显示关系路径和理由。
- 布局变化：单独开关，不计入业务改动。

祖先模块的变更数按唯一对象 ID 汇总，避免一条规则在多个视图出现时重复计数。仅调整布局时可以显示“内容无变化”。

“本次设计变更”和“实现核对结果”提供不同视图入口。设计增加了限流规则，不代表代码已经支持限流；证据过期时显示“待复核”，不继续展示旧的通过标记。

## 性能与可达性

后续完整方案拟采用可见区域裁剪和按需展开；“无限画布”描述导航空间，不承诺无限节点。基准样例暂定 100 个对象、200 条关系和四层嵌套，实际帧率及交互延迟在选定设备、浏览器上记录后再确定上限。当前四级注册示例只验证导航结构，不代表这一性能基准已通过。

不要通过超小文字塞下全系统。提供列表/大纲入口、搜索、键盘进入和返回、清晰焦点、减少动画选项，以及颜色以外的变更标记。缩放动画只帮助定位，不承担唯一的信息表达。

## 首轮原型需要回答的问题

1. 用户能否在十几秒内从全景定位登录规则，并返回原来的位置？
2. 放大时显现的内容是否恰好回答当前问题，而不是一次弹出所有细节？
3. 跨模块关系聚合后是否可解释、可追溯？
4. 同一规则更新后，所有视图和变更计数是否一致？
5. 键盘或列表入口是否能完成同样的阅读任务？

这些是待验证的体验目标，不是当前已测得的结果。
