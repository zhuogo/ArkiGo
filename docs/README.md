## 已确定的用户方向

- 面向 AI 辅助 Web 系统开发，重点是前置设计，也要服务已有系统的迭代。
- 画布可以容纳文本、图片、原型及其他媒体，支持层级嵌套与语义缩放。
- 缩远理解系统布局，放大理解模块、逻辑、边界，进一步定位代码。
- 每次迭代能看到具体变化及相关影响，AI 能按需获取上下文。
- 项目名称、目录名和 Skill 名称统一为 `arkigo`。
- Archify 源码快照仅供本地研究，不纳入本仓库；保留来源记录与固定版本的上游链接。

## 本轮建议

1. 当前先落实 `Skill + 结构化模型工具 + 通用空间画布`，MCP 按接入需求后置。
2. 设计模型是可编辑内容的来源；画布、模块摘要和 HTML 导出都从模型生成。
3. 首版先完整表达一个业务模块的一次变化，保留扩展到整个系统的结构。
4. 设计意图、代码观察结果和验证证据分别记录，界面组合展示。
5. 起步版通过对话和 Skill 修改内容；画布负责阅读、定位和布局调整，内容编辑、变更比较随后考虑。

## 如何维护这些文档

修改对象字段时同步检查示例；修改首版范围时同步修改验收条件。只在这里记录产品和技术决策，用户项目的实际设计默认放在其自身的 `docs/`，用户可指定其他位置；已有设计与 POC 沿用原路径，不自动迁移。

当前提供可独立安装的 Skill 1.0，包括按需查询、校验、程序差异、候选应用及离线画布。AI 分析与生成器渲染职责分开，生成器不自动扫描仓库。独立任务、安装与技术检查见 Skill 验收记录；用户长期维护效果仍需真实项目试用。未安装 Archify Skill，也未运行其渲染器。
