# 生成可探索的画布

仅在本轮需要画布时读取。引擎提供公共显示和交互；AI 负责根据用户输入或实际读过的代码组织系统、关系、来源和阅读顺序。不要为每个项目重新编写 HTML/CSS/JS，也不要把示例的三列布局当作固定架构。

公共界面已包含本轮确定的视觉与交互规范。生成用户项目画布时沿用模板，无需重新加载外部设计 Skill；专注内容、分区、关系和阅读顺序。

## 系统地图与详情卡片

先按 [内容组织与覆盖审阅](content.md) 确定要解释的职责、流程与关键机制，再安排画布。概览可以简洁，内容要足够具体；复杂模块需要详情或可进入的子视图承载职责、先后关系、规则、异常与数据流。不要因画布容纳不下而删减已约定的核心机制。

详情使用紧凑的独立卡片拼接：身份与摘要、职责、流程、规则、边界、相关模块分别承担阅读任务，外层只负责布局与滚动，不绘制整块面板。宽度足够时两列，窄屏单列；长段与流程占整行。`details` 继续使用现有字符串/字符串数组，不要求为样式改动协议。流程数组可用“主流程”“核心流程”“步骤”或 `steps` 命名，渲染为顺序步骤；其他数组保持普通列表，不推断业务顺序。

源码函数、来源定位与核对依据按需展开。重要边界与失败分支保持直接可读，不以折叠藏起理解主线所需的信息。标题直接命名内容，避免一个卡片重复另一个卡片的说明，也不为填满网格制造空卡片。

详情不设关闭按钮，点击卡片组外收起；点击其他节点切换，键盘可按 Esc 收起。隐藏可见滚动条，保留滚轮、触摸与键盘滚动。各类卡片用语义一致的多彩图标区分，标题与关键内容适度加粗；`details` 的字符串和列表项可用 `**关键词**` 明确指定强调。仅解析这类粗体标记，不执行或渲染输入中的 HTML，不自动猜测哪些业务事实更重要。

界面沿用系统字体、克制圆角、轻边界和浅深主题。详情首次由指针打开时，用短促的透明度/位移动效说明内容出现；频繁切换、键盘操作立即响应，减少动态效果下取消位移。动效不阻塞操作，不引入运行时网络或新依赖。

## 选择输入

- 已有 `0.1-draft` 设计模型：直接交给 `render.mjs`，适配器生成系统概览和各流程视图。它是默认阅读投影。
- 要安排特定架构布局：默认写 `docs/canvas.json`，使用 `arkigo-canvas/1`；用户指定路径或已有设计位置优先。视图按本轮需要解释的内容组织，不预设数量；分区按责任或系统边界组织，节点按真实调用或数据流安排。内容与关系优先，坐标只负责呈现。
- 同时维护模型和自定义画布时，模型是业务内容来源。画布复用对象 ID、说明与来源；修改模型后同步更新画布，不建立相互矛盾的事实。当前没有自动同步命令。

AI 阅读时使用 [查询工具](query.md) 按视图/节点取数据，不把包含公共 CSS/JS 的 HTML 全文作为日常上下文。当前输入仍是单份 JSON，子视图不是独立文件。查询工具限制返回项数和 UTF-8 字节数，带分页与省略提示；它不限制 AI 其他工具的输出，也不保证自然语言语义检索的准确率。生成器读取完整输入进行校验和打包，不要求 AI 将全文加载到上下文。只有调试显示或只剩 HTML 时才检查 HTML 中的数据与页面代码。

格式以 [画布 Schema](../schemas/canvas-v1.schema.json) 为准。下面仅展示协议语法，不是完整设计或内容颗粒度的模板；实际交付仍需满足内容指引与本轮范围。最小可运行输入：

```json
{
  "schemaVersion": "arkigo-canvas/1",
  "id": "example",
  "revision": "1",
  "title": "示例系统",
  "description": "AI 演示建议，仅覆盖一条流程，待用户审阅。",
  "views": [{
    "id": "overview",
    "title": "总架构",
    "subtitle": "用户输入经过检查后保存。",
    "zones": [{"id":"zone-core","title":"核心流程","x":36,"y":112,"width":700,"height":280}],
    "nodes": [
      {"id":"input","title":"接收输入","summary":"接收并校验请求。","kind":"入口","x":66,"y":168,"zoneId":"zone-core","sourceOrigin":"ai","designStatus":"proposed","details":{"边界":"具体校验规则待确定。"},"sources":["本轮演示建议"]},
      {"id":"save","title":"保存结果","summary":"成功后返回；失败时保留输入。","kind":"能力","x":406,"y":168,"zoneId":"zone-core","sourceOrigin":"ai","designStatus":"proposed","details":{"异常":"保存方式待确定。"},"sources":["本轮演示建议"]}
    ],
    "edges": [{"id":"input-save","from":"input","to":"save","kind":"call","label":"有效输入"}],
    "walkthrough": []
  }]
}
```

## 布局约定

- `x/y` 是画布坐标，不是屏幕像素；节点默认 `260 × 154`。视图标题占用顶部空间，分区通常从 `y:112` 开始。
- 节点须在所属分区内，左右及底部留 12、顶部留 38；初始节点不能重叠。常用横向间距 80、纵向间距 60 以上，按实际连线调整。
- 视图 ID 在文档内唯一；分区、节点、连线 ID 在各自视图内共用唯一空间。不同视图可复用同一对象 ID。
- `details` 的值为字符串或字符串数组；`sources` 是来源定位文本。不要放可执行 HTML。`sourceOrigin` 和 `designStatus` 明确观察、建议与决定的区别。
- 每个已有代码模块的 `sources` 记录项目根目录相对路径：模块标明相关目录或入口文件，关键步骤指向实际读过的文件、函数，必要时补充当次行号，例如 `src/users/register.ts — registerUser`。模型的 `provenance.references` 会由适配器传入此字段，详情面板显示为可复制文本。路径不是自动扫描或可点击打开源码的承诺；Schema 不核验文件存在。尚无代码时保留需求/对话来源，可在 `details` 中另记“计划位置”，不要将拟建路径标成代码事实。
- `targetViewId` 表示模块的子视图。所有视图必须构成单根树：可选 `rootViewId` 指定根，省略时以第一个视图为根；每个非根视图只能由一个节点拥有，不允许自指、循环、多个父节点或不可达视图。业务依赖仍用 `edges` 表达，不用子视图链接表达共享依赖。
- 连线方向表示已声明的关系；可指定 `fromSide/toSide` 为 left/right/top/bottom。引擎做避障折线和标签位置选择，不保证复杂图无交叉。
- `walkthrough` 保留为旧输入的兼容字段，浏览器不展示或执行走读；新输入写空数组即可。已有条目仍校验节点与连线引用，`edgeId` 可选且必须关联当前节点，其他 Schema 字段不变。

## 实现情况

节点可选 `implementation`，旧数据无需迁移；缺省为 `unknown`。设计决策仍用 `designStatus`，两者互不推导。画布用不同形状的彩色图标呈现，悬停、读屏和详情说明状态；不计算进度百分比或从子节点汇总父模块。

| status | 含义 | 标注要求 |
| --- | --- | --- |
| planned | 待实现：明确规划但尚未实现 | 新项目可直接标注；已有系统不能仅因未找到代码就断言未实现 |
| partial | 部分实现：仅覆盖节点描述的一部分 | 必须有 `note` 说明已覆盖与缺口，`sources` 为非空来源数组 |
| implemented | 已实现：已核对对应范围的实现 | 必须有非空 `sources`，记录实际代码/函数或明确的用户确认 |
| unknown | 未核对：尚未分析或需要重新核对 | 可用 `note` 说明原因；缺省也显示此状态 |

例如：`"implementation": {"status":"partial","note":"已有邮箱注册；手机验证码注册待开发。","sources":["src/register.ts — registerByEmail"]}`。这里的路径只说明字段形状，不能复制成用户项目事实。`note`、`sources` 是定位与说明，不是自动证据核验；Schema 不验证业务实现、文件存在、测试通过或上线。

只记录本轮需要的节点，在读代码、完成开发或讨论迭代时维护。已有功能来自代码时，设计仍可待审阅；发现设计与代码不一致，先说明差异，不静默用现状覆盖目标设计。查询摘要只包含实现状态，详情才展开说明和来源；可用 `query --implementation planned|partial|implemented|unknown` 按状态有界查找。

## 生成与交付

按当前系统的真实层级组织视图，例如系统全景 → 用户模块 → 用户注册 → 创建用户记录；层级深度由内容决定，不为凑层级新增空模块。生成用户画布无需加载开发仓库的演示文件。

带子层级的卡片用 70% 透明蒙层与层叠标记区分，不在卡片上添加“可进入”提示。顶部纯图标搜索入口打开紧凑搜索与名称列表；浅色/深色图标切换主题，首次跟随系统，手动选择在浏览器存储可用时本地记忆。

页头用面包屑表达位置，不设独立返回箭头。选中带 `targetViewId` 的节点后，可点“进入模块”、双击或继续放大进入；像浏览文件夹一样点击上一级或任意祖先面包屑返回，也可缩小到返回阈值或使用 `Alt+Left`，并恢复父级相机与模块选中。滚轮/双指每次手势最多跨一级，搜索与适应的程序定位不会自动深入。进入判断基于选中模块在可用画布中的投影大小与可见性，不按统一缩放百分比分配层级。

当前是每次渲染一层的模块钻取；进入/返回以 230ms 空间展开/收回衔接，键盘操作与减少动态效果偏好下立即切换。它不是所有层级同时存在的 LOD 渲染，也没有无限图性能承诺。

`<skill-dir>` 为此 Skill 目录：

```sh
node "<skill-dir>/scripts/render.mjs" "<project>/docs/canvas.json" "<project>/docs/canvas.html"
node "<skill-dir>/scripts/render.mjs" "<project>/docs/canvas.json" "<project>/docs/canvas.html" --layout "<project>/docs/saved.layout.json"
```

`docs/` 是 Skill 的默认产物目录，用户可指定其他目录或 HTML 文件名。CLI 仍显式接收输入和输出路径，不从当前 shell 目录猜测项目根目录；已有 POC 和已有用户项目不自动搬迁。`model.json` 与自定义 `canvas.json` 按需选用，不强制维护两份内容。

生成前会校验数据、引用和布局；失败时先按诊断修复，不覆盖已有 HTML。结构合法并不表示内容讲清：按 [阅读验收](content.md#交付前的阅读验收) 回读关键机制及覆盖清单，补齐缺失解释或明确未覆盖项。成功后打开页面，检查卡片文字、关系方向、标签、层级导航、搜索与主题；能运行浏览器时实际检查交互。没有检查过的项目如实说明。

用户在浏览器拖动的是视图坐标；节点限制在原分区，重叠落点会恢复。浏览器存储可用时自动记住位置，也可导出 `arkigo-layout/1` JSON。通过 `--layout` 重新生成时要求文档 ID 与 revision 一致；内容或初始布局改变时更新 revision，重新核对位置。导出布局不包含业务内容，不改源模型或原 HTML。

画布支持模块语义导航、平移缩放、详情、当前视图搜索、关系高亮、主题切换、拖动、保存与布局导出；走读已移除。命令行提供有界查询、程序差异和候选应用，浏览器尚不展示变更对比。全层同时 LOD、关系聚合、全仓自动分析与浏览器内容编辑未实现。AI 负责读取与分析当前范围，生成器不扫描仓库。交付 HTML 与输入 JSON 的路径，并说明分析范围。
