# 页面

`docs/arkigo/index.html` 是给人看的。它是一个文件，双击就能在浏览器里打开，不需要联网，也可以直接发给别人。每次 `change` 之后程序会重新生成它，用户刷新就能看到新内容。

本文用来向用户介绍页面。你自己不要读 `index.html`，内容用命令取。

## 两个入口

顶栏只有「地图」和「待拍板」两个入口，其余内容都从地图上走到。

| 在哪里 | 用来做什么 |
| --- | --- |
| 地图 | 看项目由哪几部分组成、彼此怎么连。模块、流程、数据、接口、界面是卡片，角色列在标题下面。两张卡片之间的全部关系合成一条线；线多的时候只画每张卡片最主要的那条，选中卡片显示它的全部关系，点线上的标签看这条线里有哪些关系。双击模块进入它的内部；进入流程看到步骤图，分支线上有条件，带失败处理的步骤有标记 |
| 详情 | 点卡片，旁边打开它的详情，这就是这一块的文档：完整内容、它里面有什么（子模块、流程、规则、验收、待定项等）、相关关系、依据和实现位置。依据旁会标出文件是正常、内容已变还是缺失。手机上点模块或流程先选中，底部给出「详情」和进入 |
| 待拍板 | 等用户决定的内容集中在这里，见下一节 |
| 查找 | 在顶栏右侧。输入时搜索标题、内容和依据；不输入时是整份设计的目录树。面板底部可以打开清单、进度和变更 |
| 清单 | 按类型列表：规则、验收、待定与决策、数据、接口、界面。可以按设计状态、实现情况、所属模块筛选。从「查找」里的「按类型列出全部」打开 |
| 进度 | 每个顶层模块有多少待实现、部分实现、已实现、未核对、需复查；验收通过了多少。点数字看到具体是哪些。点地图标题下的「实现情况」打开 |
| 变更 | 最近的修改记录：谁、什么时候、为什么改、改了哪些字段，有修改前后的对比。点顶栏的版本号打开 |

顶栏还有深浅色切换。

每个对象上有两组标记，介绍时可以向用户说明：

- 设计状态：提议（等他点头）、已接受、已作废。旁边标着来源：来自用户、AI、代码或文档。
- 实现情况：待实现、部分实现、已实现、未核对、需复查。

## 待拍板

「待拍板」列出两类内容：还没有结论的待定项，和状态是「提议」的对象。标签上的数字是等待决定的数量。用户可以：

- 对带选项的待定项**选择**一项，可以写理由；或者**否决**这个问题本身。
- 对提议**接受**或**否决**，否决可以写理由。
- 对任何对象**写批注**，用自己的话说要怎么改。批注不限于待拍板列表里的对象，在详情里也能写。

这些动作先记在浏览器里，可以逐条撤销，这时设计还没有变。做完后有两个出口交给 AI：

- **复制给 AI**：生成一段文字，粘贴到和 AI 的对话里。最方便。
- **导出决定**：下载 `decisions.json`，把文件交给 AI。

AI 写入之后页面会重新生成，用户刷新，在「变更」里能看到这次写入了什么。你收到这两种输入后怎么做，见 [loop.md](loop.md#用户在页面上拍板之后)。

## 布局

地图上卡片的位置由程序计算。用户可以拖动卡片，位置记在他的浏览器里。想让别人打开时也是这个摆法，就在页面上导出布局文件交给你，你执行 `arkigo layout import <文件>`。`arkigo layout reset` 回到自动排布。

## 常见情况

- **用户说页面没变**：让他刷新。还不对就执行 `arkigo render`，并确认他打开的是这个项目的 `docs/arkigo/index.html`。
- **用户想点文件路径直接打开编辑器**：`arkigo render --editor vscode`（或 `cursor`），之后的修改会沿用这个设置。这样生成的页面里带有本机的项目路径，只适合在本机看；要把页面发给别人或提交到仓库时，先执行一次不带 `--editor` 的 `arkigo render`。
- **用户要一份能发出去的文档**：页面本身就能发；要 Markdown 时用 `arkigo export md --out <文件>`。
- **用户在页面上找不到某件事**：用顶栏的「查找」。还找不到，说明设计里没有写，该补的是设计。
